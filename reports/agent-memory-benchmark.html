01 / METHODOLOGY

测试如何进行

统一数据、问题、回答模型与最终记忆预算。重点比较可部署配置的实际效果，托管服务内部的抽取模型无法统一控制。

01

分层抽样

按 ID、类别与固定 seed 选题，7 类各 2 题；不按答案或成绩筛选。

02

导入完整历史

按原始日期排序，保留角色与会话边界；每块约 3K tokens、最多 20 条消息。

03

等待记忆生成

检查异步抽取状态，重试限速失败；普通策略至少等待 300 秒，Episodic 1,200 秒。

04

检索与融合

各分支最多取 100 条；SPU/SPUE 按排名交错合并，再共用 4K 预算。

05

统一生成回答

Haiku 4.5 读取问题与实际记忆上下文；不把标准答案注入记忆。

06

评分与复判

Sonnet 4.5 使用 LongMemEval 评分提示词；复判全部固定答案，保留首轮分数。

07

补充检索诊断

检查 12 道可回答题的 22 个标注事实，在候选与实际可见文本中是否被覆盖。

Mem0 OSS 配置mem0ai 2.2.1 + Qdrant 1.20.1；默认事实抽取与混合检索，关闭 reranker。Haiku 4.5 抽取，Titan Text Embeddings V2 向量化。
AgentCore 策略配置Semantic、Preference、Summary、Episodic 分别创建独立 Memory。SPU = 前三者；SPUE 再加入 Episodic。
预算与隔离每题独立 actor/user_id；最终记忆正文使用 cl100k_base 计数，包含分隔符及返回的时间字段，不是完整模型输入长度。
可检索时间的边界CreateEvent 成功仅代表接受事件。快照稳定、等待窗口与无可见失败任务，并不构成后台所有抽取和 reflection 已结束的权威证明。
公平性边界：单分支最多 100 条候选，SPU/SPUE 可合计 300/400 条，检索工作量不同；比较时优先同时查看实际4K覆盖、调用开销和延迟。组合结果不代表单个 Memory 内多策略共同运行的性能。

指标怎么读

事实 Recall@K
前K条候选支持的不同标注事实数 ÷ 本题标注事实总数，再对题目等权平均。它不是来源会话命中率。
Precision@K / Hit@K
前K个位置中相关记录的占比；不足K条的空位计为不相关。Hit只要求至少一条记录支持一个事实。
MRR@10 / pooled nDCG@10
MRR反映第一条相关记录出现得多早。nDCG采用二值相关性，用所有方案的共同候选去重池构造理想排序，并非全库穷举的官方nDCG。
实际4K事实召回 / 全事实覆盖题数
前者统计实际可见事实比例；后者要求本题所有标注事实都在上下文中。4K可能容纳超过10条短记录，因此可高于Recall@10。
不能只看 Precision：不同系统的记录长度与粒度不同；一条长摘要与一条短事实不是等量单元。多条相关记录也可能重复表达同一事实。

05 / FAILURE ANALYSIS

三个决定结论边界的案例

上下文预算 / 杂志订阅题

加上 Episodic 后，关键订阅被挤出

Architectural Digest 的事实仍在候选中，但较长记录占用4K预算后没有进入回答上下文，SPUE只回答一份订阅。

SPU → SPUE 该题由对变错

这是当前融合与截断方式的失败案例，不能解释全部分数差异，也不证明Episodic本身无用。

时间标签 / 鸡尾酒与小说题

核心事实存在，问题时间前提可疑

鸡尾酒题的提问日期与证据中的“上周末”参照不同；小说题的440与416页有证据，但未支持问题指定的一月、三月。

12题 / 10题 保留敏感性分析

原问答分数未改。12题检索诊断仅核验核心事实，另提供排除两题后的10题结果。

评分可靠性 / 固定答案复判

判分重复一致，仍可能重复出错

鸡尾酒题Episodic拒答却被判对；住址前提错误题SPUE给出相符拒答说明却被判错，回答还伴有日期推理问题。

126/126 两次判分一致

复判衡量重复性；需要独立人工校准来判断正确性。发现疑点后没有修改首轮得分。

07 / CONCLUSIONS

本轮能够支持的选型结论

继续重点比较 Mem0 与 SPU

两者实际4K事实覆盖均达到100%，当前一题分差无法证明稳定优劣。下一轮需要扩大题量，先校准时间标签与评分规则，再评估质量差异。

Summary 是通用单策略候选，尚非已证实的最佳选择

Summary信息覆盖较好，Semantic本轮答题数更多。应保留两者作单策略基线，并按业务中的助手信息、用户事实、偏好等需求决定组合。

融合策略要管理冗余、排名与长度

更多策略并不自动带来更高成绩。可在后续实验比较去重、重排、分支预算分配与压缩，但本轮并未验证这些改进的收益。

Episodic 需要独立的执行任务评测

本轮只有对话问答，无法验证工具执行成功率、经验迁移或动作复用。应增加真实工具轨迹和重复任务，再决定其部署价值。

生产选型补齐成本、延迟与可靠性

用真实业务流量、多次重复及实际并行服务测试，补充隔离、删除、可检索延迟和运维成本。当前结果适合筛选候选方案。

阅读结论时保留这些限制

  • 仅14题、每类2题；检索诊断仅12题，不能据此建立稳定产品排名。
  • 不是正式AML提交，也不是完整LongMemEval成绩；任务覆盖与评分聚合方式不同。
  • Mem0测的是OSS默认配置，不代表托管Platform；AgentCore内部抽取模型不可控。
  • 标注事实全部可见不保证回答正确；偏好题的完整事实覆盖要求可能严于原答题评分。
  • Summary部分记录返回2026年处理时间，其他记录返回2023年历史时间；裸时间字段不能被直接视为事件日期。
  • 同一Sonnet模型完成两阶段事实核验；未完成独立人工或跨模型一致性验证。
  • 组合复用独立资源的候选，额外检索工作量需要计入比较。

本报告的数据口径

QA使用原始首轮结果；检索诊断使用完成复核与明确裁决后的最终汇总。敏感性开关只改变检索诊断题集，不改变14题的原始答题成绩。
